Workflow

  1. Draft. Upload questions or write them in the UI.
  2. In review. Submit for a second pair of eyes.
  3. Approved. Reviewer (different person) signs off.
  4. Locked. Frozen — ready to run against models.

Two-person rule

The approver can never be the author. We enforce this at the database and audit-log level so the rule survives even when someone clicks fast.

Reproducibility

Only locked sets can be evaluated. Every run keeps the raw model output, provider metadata, parsed answers, and per-category scores in Postgres for later diffing.
